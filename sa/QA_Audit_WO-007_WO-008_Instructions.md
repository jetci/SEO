## 🎯 คำแนะนำและขั้นตอนการตรวจรับงาน (Test Cases สำหรับ QA)

ฝ่ายตรวจสอบสามารถนำหัวข้อต่อไปนี้ไปใช้ทดสอบระบบจริงได้ทันทีครับ:

### 1. หมวด Pipeline & การเขียนบทความ (WO-PIPELINE-007)

*   **Test Case 1.1: การบังคับตั้งค่า API Key (WP-B3)**
    *   **วิธีทดสอบ:** หากคุณมี Account เปล่าที่ยังไม่ได้ตั้งค่า LLM API Key ให้ลองเข้าไปหน้าเขียนบทความ (Write) และกดสร้างบทความ
    *   **ผลที่คาดหวัง:** ระบบจะต้องแจ้งเตือน (Error) ทันทีว่ายังไม่มี Key และต้องมีข้อความแนะนำให้ไปตั้งค่าที่เมนู Settings ไม่ใช่แค่ Error เปล่าๆ
*   **Test Case 1.2: การบล็อกบทความที่ไม่มี Research Package (WP-B2)**
    *   **วิธีทดสอบ:** ลองเลือก Keyword ที่ยังไม่ได้ทำ Research (หรือข้ามขั้นตอน Research) แล้วกดสร้างบทความ
    *   **ผลที่คาดหวัง:** ระบบจะต้องป้องกันไม่ให้สร้างบทความ และแจ้งให้กลับไปทำ Research ก่อน (ป้องกันปัญหาบทความที่ได้ออกมาเป็น Generic หรือภาพรวมกว้างๆ)
*   **Test Case 1.3: รูปแบบข้อความแจ้งเตือนเมื่อเกิด Error (WP-A1 & WP-B5)**
    *   **ผลที่คาดหวัง:** 
        1. หากเกิด Error หนักๆ ตอนดึง LLM (เช่น เครดิตหมด หรือ Model ผิด) หัวข้อ Error จะแยกประเภทชัดเจน ไม่เหมารวมว่าเป็น "Transient Limit" 
        2. หากมีการสร้าง Placeholder (บทความชั่วคราวตอน Error) จะไม่มีเครื่องหมาย `###` โผล่มาในเนื้อหา (จะใช้สัญลักษณ์ `✦` แทนเพื่อไม่ให้ Frontend สับสนและตัด Section ผิด)

### 2. หมวด การตั้งค่าระบบ Settings & สิทธิ์การเข้าถึง (WO-SETTINGS-008)

*   **Test Case 2.1: การแสดงผลการตั้งค่าตามสิทธิ์ (SET-02 & SET-07)**
    *   **วิธีทดสอบ (Admin):** ล็อกอินด้วยบัญชี Admin/Owner ไปที่หน้า KCP `->` Settings
    *   **ผลที่คาดหวัง:** จะเห็นแบบฟอร์มให้กรอก API Key / Provider และสามารถกดปุ่ม Save ได้ตามปกติ (ฟอร์มแสดงผลครบถ้วน)
    *   **วิธีทดสอบ (Writer):** ลองใช้บัญชีที่มีสิทธิ์เป็นแค่ Member/Writer เข้าไปที่หน้า Settings
    *   **ผลที่คาดหวัง:** หน้าจอจะถูกบล็อก และแสดงผลเป็นหน้าการ์ดสีแดง (FORBIDDEN) "สิทธิ์ไม่เพียงพอ" หรือ "ปิดใช้งานการแก้ไข" จะไม่เห็นฟอร์มใดๆ
*   **Test Case 2.2: รูปแบบการเซ็นเซอร์ API Key (SET-10)**
    *   **วิธีทดสอบ:** ในหน้า Settings ฝั่ง Admin เมื่อกรอก Key ไปแล้วและบันทึก ให้ดูรูปแบบ Key ที่โชว์ในช่อง
    *   **ผลที่คาดหวัง:** Key จะถูกเซ็นเซอร์เป็น **8 ดาวตรงกลาง** (เช่น `sk-o********46a6`) ซึ่งรูปแบบนี้จะใช้ตรงกันทั้งระบบ (ไม่ว่าจะเป็น Settings หน้าบ้าน หรือ Admin หลังบ้าน)
*   **Test Case 2.3: ปัญหาเซฟผิดทีม (SET-03)**
    *   **วิธีทดสอบ:** Admin ทำการเปลี่ยนแปลงข้อมูลการตั้งค่าและกด Save 
    *   **ผลที่คาดหวัง:** ข้อมูลจะถูกบันทึกอย่างถูกต้องในทีมปัจจุบันเสมอ จะไม่มีอาการบันทึกลง Team ID = 0 จน Key หายอีกต่อไป
