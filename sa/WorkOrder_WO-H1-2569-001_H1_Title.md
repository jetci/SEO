## 1. อาการที่รายงาน

ในขั้นตอนการเขียนบทความ ผู้ใช้ไม่เห็น H1 (หัวข้อเรื่องของบทความ) ปรากฏในขั้นตอนใดเลย ไม่มีช่องให้ดูหรือแก้ไข H1 เป็นเอกเทศ ตั้งแต่ Step 1 จนถึง Step ประกอบร่าง ทำให้ผู้ใช้ควบคุมหัวข้อบทความไม่ได้

## 2. สาเหตุที่แท้จริง (Root Cause)

ระบบไม่แยก 3 สิ่งนี้ออกจากกัน ทำให้ H1 ไม่มี 'ที่ยืน' ของตัวเองใน UI:

| ฟิลด์ | ความหมาย | สถานะปัจจุบัน |
|---|---|---|
| Keyword | คำค้นเป้าหมาย เช่น 'วิธีเลี้ยงกุ้ง' | มีช่องใน Step 1 |
| **H1 / Title** | หัวข้อเรื่องของบทความ | **ไม่มีช่องใน UI เลย** |
| Meta Title | ชื่อที่โชว์บน Google SERP (≤60 ตัวอักษร) | มีช่องใน Step 5 |

**ผลที่ตามมา:**
- Backend สร้าง `title` (H1) จริง เก็บใน `articles.title` และ assemble เป็น `# ${title}` ที่หัว markdown — แต่ Frontend ไม่มีช่องแสดง/แก้ H1
- เพราะไม่มีที่วาง H1 โค้ดจึงเอา title ไปยัดใส่ช่อง Keyword แทน (`setKeyword(title)`) ทำให้ทั้งสองค่าปนกัน
- Outline (Step 3) มีคำสั่ง `if (heading_level === 1) continue` = ข้าม H1 ไม่แสดงยอด outline
- H1 จึงโผล่ครั้งเดียวที่ Step พรีวิว และหายไปถ้า BE ไม่ได้ prepend

## 3. รายการงานที่ต้องแก้ไข (Tasks)

### งานที่ 3.1 — เพิ่มช่อง H1 / หัวข้อเรื่อง เป็นเอกเทศใน UI
- **ไฟล์:** `client/src/pages/WritePage.tsx`
- **ตำแหน่ง:** Step 5 (assemble) ก่อนช่อง Meta Title ที่ L2283 และแสดง read-only ตั้งแต่ Step 3/4
- **สิ่งที่ทำ:** เพิ่ม state `h1`/`setH1` แยกจาก `keyword` และ `mt` + เพิ่ม input 'หัวข้อเรื่อง (H1)' พร้อมตัวนับความยาว
- **หมายเหตุ:** H1 กับ Meta Title เป็นคนละค่า — H1 คือหัวบทความ (ยาวได้ถึง ~512), Meta Title คือชื่อบน SERP (≤60)

### งานที่ 3.2 — เลิกเอา title (H1) ไปยัดใส่ช่อง Keyword
- **ไฟล์:** `client/src/pages/WritePage.tsx`
- **ตำแหน่งที่ต้องแก้:** L355 `setKeywordRaw(title...)`, L606-608 `firstH1 → setKeyword`, L801 `r.outline.title → setKeyword`, L1221 `r.title → setKeyword`
- **สิ่งที่ทำ:** เปลี่ยนทุกจุดที่ `setKeyword(title/H1)` ให้เป็น `setH1(title)` แทน — Keyword ต้องมาจาก focus keyword ของ KCP เท่านั้น
- **อ้างอิงบั๊กเดิม:** มีคอมเมนต์ในโค้ด L353 เตือนบั๊กนี้อยู่แล้ว

### งานที่ 3.3 — แสดง H1 ที่ยอด Outline (Step 3)
- **ไฟล์:** `WritePage.tsx` (outlineSecs) + ตรวจ `articleWriterService.ts` L325
- **สิ่งที่ทำ:** แสดง H1 เป็นแถวบนสุดของ outline (อ่าน/แก้ได้) แม้ backend จะ `continue` ข้ามการเขียน body ของ H1 ก็ตาม — การข้าม body ถูกต้อง แต่การแสดงหัวข้อต้องมี
- **ผลลัพธ์:** ผู้ใช้เห็นโครงเรื่องครบ: H1 (เรื่อง) → H2/H3 (หัวข้อย่อย)

### งานที่ 3.4 — เชื่อม H1 เข้ากับการบันทึกและประกอบร่าง
- **Backend (พร้อมแล้ว):** `saveDraft` รับ `title` อยู่แล้ว (write.ts L564, L582) และ `getDraft` คืน `title` อยู่แล้ว (L329/384) — ไม่ต้องแก้ schema
- **Frontend:** เวลา `saveDraft` ส่งค่าจากช่อง H1 ใหม่ไปที่ field `title`; เวลา `getDraft` เติม `d.title` ลงช่อง H1 (ไม่ใช่ setKeyword)
- **ประกอบร่าง:** ยืนยัน assemble ยัง prepend `# ${title}` ที่ L479 — ถ้าผู้ใช้แก้ H1 ต้องใช้ค่าที่แก้

### งานที่ 3.5 — แสดง H1 ในพรีวิว SERP และ Export
- **ไฟล์:** `WritePage.tsx` (renderMdSafe / SERP preview L2602, export L2743)
- **สิ่งที่ทำ:** พรีวิวขึ้น H1 ที่หัว · Export HTML/DOCX ใช้ H1 เป็น `<h1>`/Heading1 และใช้ Meta Title เป็น `<title>` แยกกัน

## 5. หมายเหตุ

- Backend เก็บ/คืน `title` ครบแล้ว งานหลัก ~80% อยู่ที่ Frontend
- ไม่ต้องแก้ database schema — `articles.title` มีอยู่แล้ว (varchar 512)
- งานนี้แยกอิสระจากบั๊ก RBAC/placeholder ทำก่อนได้ทันที
- ระวัง: อย่าสับสน H1 (หัวเรื่อง) กับ Meta Title (ชื่อ SERP) — คนละฟิลด์ คนละความยาว
